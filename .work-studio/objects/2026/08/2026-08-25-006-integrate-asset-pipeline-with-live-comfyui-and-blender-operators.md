## Intent

Integrate the asset pipeline state machine (proven in 2026-08-24-020) with live ComfyUI (COMP-043) and Blender (COMP-042) operators. Replace simulated operator calls with actual operator dispatch through the production skill system. Test the full 6-stage pipeline (concept -> mesh -> cleanup -> material -> rig -> registered) with real ComfyUI and Blender operations.

Parent: WO `2026-08-23-001` §5.1. Component: COMP-048.

## Success evidence

- [ ] Asset pipeline calls live ComfyUI operator for concept art generation
- [ ] Asset pipeline calls live ComfyUI operator for 3D mesh generation (Hunyuan3D-2)
- [ ] Asset pipeline calls live Blender operator for import/cleanup/material/rig
- [ ] State machine tracks progress through all 6 stages with live operators
- [ ] Resume-from-failure works with live operators
- [ ] Asset registered in registry after successful pipeline completion


## Constraints and non-goals

**Constraints:**
- Must use Layer 1 operators (ComfyUI, Blender) — never calls tools directly
- Must respect GPU claims through COMP-041 protocol
- Must handle operator failures gracefully (retry up to 3 times)
- Must persist state in Asset Work Object for resume capability

**Non-goals:**
- No production hardening or scale testing
- No director approval gates (separate Work Object)
- No visual critic integration (separate Work Object)
- No asset design decisions (director's authority)

### Decision 1 — Operator adapter layer (Direction 2)

| Field | Value |
|-------|-------|
| **Decision type** | decision |
| **Result** | pass |
| **Scope** | Integration approach: create an adapter layer between the asset pipeline and the operators. The adapter translates pipeline stage calls into operator API calls, handles operator-specific errors, and provides a uniform interface. Decouples pipeline from operator implementation details. |
| **Authorization** | Director selection from 3 differentiated directions generated by develop-idea. |
| **Confidence** | high — decouples pipeline from operator details, easier to swap operators later. |
| **Actor** | director |
| **Revisit trigger** | If operator APIs are stable and unlikely to change, consider simplifying to direct calls. If the skill system becomes the standard dispatch mechanism, consider switching to skill system dispatch. |
| **Rationale** | Director selected operator adapter layer over direct calls (too tightly coupled) and skill system dispatch (may add overhead). Adapter layer decouples pipeline from operator details, making it easier to swap operators or add new ones. |

### Decision 2 — Tracer bullet: ComfyUIAdapter with uniform interface

| Field | Value |
|-------|-------|
| **Decision type** | decision |
| **Result** | pass |
| **Scope** | Smallest end-to-end slice testing the adapter layer assumption: create an adapter layer with ComfyUIAdapter implementing uniform interface (submit_job, poll_status, get_result). Test with one asset through the concept stage (ComfyUI) only. Verify the adapter correctly translates the call and handles the result. |
| **Authorization** | Director acceptance of tracer-bullet design. |
| **Confidence** | high — tests the riskiest assumption (adapter can translate pipeline calls to operator API calls uniformly). |
| **Actor** | director |
| **Revisit trigger** | If the adapter fails to translate the call, the tracer exposes the failure mode clearly. If operator APIs are unstable, the adapter layer adds value. |
| **Rationale** | Tests ComfyUIAdapter only with uniform interface, proving the adapter layer pattern before building the full integration. Non-goals: no full pipeline integration, no Blender adapter testing, no retry logic at the adapter level. |
