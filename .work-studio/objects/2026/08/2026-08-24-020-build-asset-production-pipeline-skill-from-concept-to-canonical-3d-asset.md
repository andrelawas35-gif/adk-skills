## Intent

Manage the lifecycle of a 3D asset from concept through to a canonical .blend
file registered in the asset registry. Orchestrates the pipeline: concept art
(ComfyUI Flux) → 3D mesh generation (Hunyuan3D-2) → Blender import and
cleanup → material assignment → rig (if character) → register in asset
registry. Each stage uses Layer 1 operators; this skill sequences them and
tracks asset state.

Parent: WO `2026-08-23-001` §5.1. Component: COMP-048.

## Success evidence

- [ ] Can initiate asset creation from a text description or concept image
- [ ] Orchestrates ComfyUI (concept art) → ComfyUI (3D mesh) → Blender (import/cleanup)
- [ ] Registers completed asset in `.work-studio/asset-registry.md`
- [ ] Tracks asset state through pipeline stages
- [ ] Creates an Asset Work Object for each canonical .blend file


## Constraints and non-goals

**Constraints:**
- Must use Layer 1 operators — never calls Blender/ComfyUI directly
- Must register assets in the registry before they can be used by scene planner
- GPU claims flow through operators, not this pipeline

**Non-goals:**
- No manual sculpting or detailed mesh editing
- No texture painting (out of scope for automation)
- No asset design decisions (director's authority)

### Decision 1 — State-machine asset tracker (Direction 2)

| Field | Value |
|-------|-------|
| **Decision type** | decision |
| **Result** | pass |
| **Scope** | Asset pipeline skill architecture: state machine with 6 states (concept → mesh → cleanup → material → rig → registered). Each transition calls the appropriate Layer 1 operator. State persisted in Asset Work Object frontmatter. Resume-from-state on failure. Retry individual stages up to 3 times before marking asset as failed. |
| **Authorization** | Director selection from 4 differentiated directions generated by develop-idea. |
| **Confidence** | high — operators are verified (2026-08-24-014 Blender, 2026-08-24-015 ComfyUI); state machine adds resilience justified by production use case. |
| **Actor** | director |
| **Revisit trigger** | If operators prove reliable enough that retry/resume is never needed in practice, consider simplifying to linear sequencer. If pipeline stages change (e.g., add texture stage), state machine needs updating. |
| **Rationale** | Director selected state-machine over linear sequencer (too simple for production), deep registry integration (too complex for v1), and director gates (slows pipeline). State machine balances resilience with complexity. |

### Decision 2 — Tracer bullet: 3-stage state machine with simulated failure and resume

| Field | Value |
|-------|-------|
| **Decision type** | decision |
| **Result** | pass |
| **Scope** | Smallest end-to-end slice testing the state-machine assumption: run a simple prop (cube) through 3 stages (concept → mesh → cleanup). Simulate a failure at mesh stage by injecting a recoverable error. Resume from mesh stage. Verify asset completes successfully and state machine correctly tracks progress. |
| **Authorization** | Director acceptance of tracer-bullet design. |
| **Confidence** | high — tests the riskiest assumption (resume-from-state) with minimal complexity. |
| **Actor** | director |
| **Revisit trigger** | If resume fails, the tracer exposes the failure mode clearly. If operators are unreliable, the tracer reveals whether retry adds value. |
| **Rationale** | Tests 3 of 6 stages with a simulated failure and resume, proving the state machine works before building the full pipeline. Non-goals: no production hardening, no full 6-stage pipeline, no real asset complexity, no registry integration, no director gates. |

### Decision 3 — Full 6-stage pipeline design

| Field | Value |
|-------|-------|
| **Decision type** | decision |
| **Result** | pass |
| **Scope** | Extend the proven 3-stage pattern to all 6 stages: concept -> mesh -> cleanup -> material -> rig -> registered. Each stage calls the appropriate Layer 1 operator (ComfyUI for concept/mesh, Blender for cleanup/material/rig). The registered stage creates the Asset Work Object and registers in the asset registry. |
| **Authorization** | Director acceptance of full pipeline design. |
| **Confidence** | high — extends proven 3-stage pattern. |
