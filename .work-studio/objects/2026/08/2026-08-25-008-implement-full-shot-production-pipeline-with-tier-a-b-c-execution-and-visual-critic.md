## Intent

Implement the full shot production pipeline that `2026-08-24-021` proved
feasible. Route each shot through tiered execution: Tier A (fast sketch —
rough 3D blocking, proxy lighting, minutes), Tier B (refined — full scene
assembly, proper materials, draft render), Tier C (final — full-quality
render, compositing). Integrate the visual critic (`2026-08-24-019`) at each
tier gate. Create and maintain Shot Work Objects. Orchestrate scene planner
(`2026-08-24-017`), Blender operator (`2026-08-24-014`), and visual critic
per tier. Each tier escalation requires director approval.

Parent: WO `2026-08-23-001` §5.5. Component: COMP-049.
Predecessor: WO `2026-08-24-021` (state-machine tracer bullet, closed).

- No direct tool execution (delegates to Layer 1/2 operators)

- No re-proving the state-machine pattern (already done in predecessor)

### Decision 2 — Single WO + single-pass critic for v1; iterative loop deferred to v2

- **Branch chosen**: Single Work Object with tier state (shot_status, shot_tier frontmatter) + single-pass visual critic per tier. Critic evaluates once after render; if issues found, escalate to director for approve/retry decision. No internal feedback loop within tiers.
- **Alternatives considered**:
  - Iterative critic loop within each tier (Dir 2) — rejected for v1 because: (a) scene planner has no feedback consumption path (takes prompt + registry, not critique), (b) visual critic is tracer-only, (c) building an adjustment layer between critic and planner is a new component, not an integration.
  - Linked tier Work Objects (Dir 4) — rejected because: (a) no existing tier-WO pattern in codebase, (b) 5-level hierarchy adds navigation complexity, (c) side-by-side tier comparison is theoretical — no evidence directors need it yet.
  - Async director gates with auto-proceed (Dir 3) — rejected because: (a) cost of proceeding on suboptimal render (wasted GPU + re-render) not justified, (b) director gate is already a constraint.
- **Rationale**: Asset pipeline (2026-08-24-020) and shot tracer (2026-08-24-021) both used single WOs — proven pattern. The `shot_status` and `shot_tier` frontmatter fields already exist (2026-08-24-006). Single-pass critic uses existing components as-is. Iteration can be added later once the critic is proven in production.
- **Trade-offs accepted**: Lower quality per tier (no automatic refinement), more director involvement (approve/retry per tier). Acceptable because director gate is already a constraint.
- **Confidence**: high — grounded in [system] evidence from two proven pipelines and actual capability gaps in scene planner/critic interfaces.
- **Edge cases noted**: If a tier fails and needs retry, the retry's evidence appends to the same WO — interleaved with the failed attempt. Mitigated by tagging entries with `tier_a_attempt_1`/`tier_a_attempt_2` markers.
- **Revisit trigger**: First production render where the critic's `staging_recommendations` contain structured adjustment instructions (object name + parameter + delta) rather than abstract suggestions. Also revisit if director explicitly requests side-by-side tier comparison.
- **Actor**: director (accepted recommendation)

### Decision 3 — Tracer bullet accepted: Tier A end-to-end slice (scene planner -> adapter -> Blender queue -> render -> visual critic)

Visual critic evaluates one render → produces critique with `escalation_needed` flag. Single pass only — no retry, no director gate, no iteration. |
| **Authorization** | Director acceptance of tracer-bullet design. Local test authority only; headless Blender subprocess; no production access. |
| **Confidence** | high that the scene planner and Blender operator individually work (both proven); medium that the handoff works (never tested) — this is exactly what the tracer tests. |
