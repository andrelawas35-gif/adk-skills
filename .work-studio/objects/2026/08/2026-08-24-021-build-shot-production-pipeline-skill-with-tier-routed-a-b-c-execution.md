## Intent

Manage a shot's lifecycle from screenplay breakdown through final render.
Routes each shot through tiered execution: Tier A (fast sketch — rough 3D
blocking, proxy lighting), Tier B (refined — full scene assembly, proper
materials, draft render), Tier C (final — full-quality render, compositing).
Creates and maintains Shot Work Objects. Orchestrates scene planner, operators,
and visual critic per tier.

Parent: WO `2026-08-23-001` §5.5. Component: COMP-049.

## Success evidence

- [ ] Creates Shot Work Objects from screenplay breakdown
- [ ] Routes shots through Tier A → B → C execution stages
- [ ] Tier A produces rough blocking render within minutes
- [ ] Each tier escalation requires director approval
- [ ] Tracks shot status, version history, and render outputs
- [ ] Coordinates scene planner, Blender operator, and visual critic per shot


## Constraints and non-goals

**Constraints:**
- Tier escalation requires explicit director approval
- Shot state is durable in a Work Object, not ephemeral
- Must respect protect fields on locked shots

**Non-goals:**
- No editorial decisions about shot selection or sequencing (belongs to animatic pipeline)
- No direct tool execution (delegates to Layer 1/2)
- No final cut authority

### Decision 1 — State-machine shot tracker (Direction 2)

| Field | Value |
|-------|-------|
| **Decision type** | decision |
| **Result** | pass |
| **Scope** | Shot pipeline skill architecture: state machine with tier progression (breakdown → tier_a → tier_b → tier_c → final). Each tier transition calls the appropriate operator. State persisted in Shot Work Object frontmatter. Resume-from-state on failure. Retry individual tiers up to 3 times before marking shot as failed. |
| **Authorization** | Director selection from 4 differentiated directions generated by develop-idea. |
| **Confidence** | high — asset pipeline (2026-08-24-020) proved the state-machine pattern. |
| **Actor** | director |
| **Revisit trigger** | If operators prove reliable enough that retry/resume is never needed in practice, consider simplifying to linear sequencer. If visual critic (2026-08-24-019) is not ready, pipeline needs to handle that gracefully. |
| **Rationale** | Director selected state-machine over linear sequencer (too simple for production), deep registry integration (too complex for v1), and director gates (slows pipeline). Asset pipeline proved the pattern. Retry/resume valuable for production shots. |

### Decision 2 — Tracer bullet: Tier A state machine with simulated failure and resume

| Field | Value |
|-------|-------|
| **Decision type** | decision |
| **Result** | pass |
| **Scope** | Smallest end-to-end slice testing the shot state-machine assumption: run one shot through Tier A (fast sketch) only. Simulate a failure at Tier A by injecting a recoverable error. Resume from Tier A. Verify shot completes Tier A and state machine correctly tracks progress. |
| **Authorization** | Director acceptance of tracer-bullet design. |
| **Confidence** | high — tests the riskiest assumption (resume-from-state) with minimal complexity. |
| **Actor** | director |
| **Revisit trigger** | If resume fails, the tracer exposes the failure mode clearly. If operators are unreliable, the tracer reveals whether retry adds value. |
| **Rationale** | Tests Tier A only with simulated failure and resume, proving the state-machine pattern before building the full tiered pipeline. Non-goals: no Tier B or Tier C, no visual critic integration, no director approval gates, no shot registry integration. |
