# Project Studio

Turn attention into evidence-bearing work. A project is a bounded encounter with reality that changes what the user can see, make, or judge—not a performance of productivity.

## Personal project lens

Build from the user's live concerns: systems and lived experience; maps, routes, borders, and circulation; logistics and labor; law, economics, software, and storytelling; and the gap between institutional categories and a self-authored life.

Do not force these themes onto every project. Begin with what the user actually notices or keeps returning to. Favor a particular place, person, route, rule, tool, transaction, or story over an abstract topic. The aim is distinct evidence, not an impressive-sounding project.

## Studio cycle

1. **Find the live question.** Retrieve related material with `maintain-personal-memory` when an archive exists. Prefer a question that appears in two dated records; if the interest is new, treat it as a one-project probe rather than a recurring identity.
2. **Define a hypothesis.** State what the user expects to find, make, or learn. Make it falsifiable or revisable.
3. **Choose one encounter with reality.** Require a field observation, conversation, document, route trace, small transaction, public record, prototype test, or other direct contact. Reading or prompting alone is not an encounter.
4. **Make one artifact.** Produce a memo, annotated map, interview note, photo essay, comparison, short scene, script, data sketch, prototype, or other object that carries the evidence forward.
5. **Review the difference.** Compare the hypothesis with what happened. Record what changed, what stayed unclear, and the next question.

Keep the first cycle small enough to finish within seven days unless the user explicitly chooses a longer scope. Prefer reversible tests over commitments.

## Project brief

Return this brief before proposing detailed execution:

```markdown
## Project — [working title]

### Live question

[A specific question in the user's language. Cite prior records if available.]

### Hypothesis

[What the user currently expects; label it as provisional.]

### Encounter

[One direct contact with reality: who/what, where, and what will be observed or asked.]

### Artifact

[One finishable object and its intended reader or use.]

### Review question

[What result would change the user's current view?]

### Scope

- **Timebox:** [e.g., 3 hours, one afternoon, 7 days]
- **First action:** [A concrete action the user can take]
- **Constraint:** [Access, cost, privacy, safety, or ethical limit]
```

Ask one precise clarification only when the encounter, artifact, or constraint cannot be chosen responsibly. Otherwise make a small, reversible proposal and name the assumptions.

## Choosing an encounter and artifact

Match the project to the question:

| If the question concerns… | Favor an encounter | Favor an artifact |
| --- | --- | --- |
| A route, border, or circulation | Trace one route; observe a transfer point | Annotated map or route memo |
| Work or logistics | Observe a workflow; speak to a participant | Field note, process map, or short interview |
| Law or economics | Compare a rule, contract, price, or public record to its effect | Plain-language comparison or case memo |
| Software or systems | Prototype one interaction; test it with a real task | Small demo, walkthrough, or failure log |
| A social story or lived tension | Gather one scene or conversation with consent | Short scene, audio note, or essay fragment |

Never invent a field encounter, misrepresent the user's role, pressure someone to participate, or collect sensitive information without a clear reason and consent.

## Review and memory handoff

After the project, use `capture-lived-evidence` for raw field material and `maintain-personal-memory` to update the project record. Separate:

- **What happened** from **what it might mean**
- **The artifact** from **the user's identity**
- **A useful next question** from **an obligation to continue**

Use this review:

```markdown
## Project review

- **Hypothesis:** [Original expectation]
- **Encountered:** [What actually happened]
- **Artifact made:** [Link or description]
- **Changed:** [What the evidence revised]
- **Still unclear:** [Open question]
- **Next move:** stop | repeat | deepen | share | start a different question
```

Do not convert a single project into a principle or identity claim. Let repeated work earn that status.
